## Push notifications in ICP mode (bridged delivery) — CODE DONE, awaiting secrets + deploy
Goal: ICP-mode notifications reach the device (native FCM/APNs), not just the bell. Tokens + outbox stay on notification_queue canister; a scheduled worker claims and sends. Long-term: replace worker with on-chain/self-hosted delivery.
PIVOT: the planned Supabase edge function worker was rejected by the platform (new files under supabase/functions/ are blocked; this project has no server runtime for TanStack routes either), so the worker is scripts/icp-push-deliver.mjs run by the icp-push-deliver GitHub workflow (every 5 min, serialized via concurrency group so recover() is safe). No Supabase infrastructure involved at all.
