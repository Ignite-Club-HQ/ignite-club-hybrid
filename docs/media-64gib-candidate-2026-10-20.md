# 64 GiB photo-store candidate

## What changed

- Opt-in stable-backed setting accepts up to 68,719,476,736 bytes (64 GiB); heap-backed stores remain capped at 2 GiB.
- Existing saved capacity is unchanged by upgrade. Enlargement remains a separate governor action.
- The existing 80% finalized-plus-pending admission limit remains: 54,975,581,388 bytes at 64 GiB. This is not a guarantee of usable payload or simultaneous club entitlements.
- Physical allocation stops at 68,652,367,872 bytes (64 GiB minus a conservative 64 MiB runtime reserve). The reserve is policy, not measured runtime overhead. Fragmentation or runtime allocation failure can close the store earlier.
- Combined Pro allowance, purchased allowance, metadata cap, encryption, club placement and local-only multi-store growth prototypes are unchanged. Prototype router growth-budget limits are intentionally not raised: this is in-place single-store enlargement, not activation of multi-store commitments.

## Local evidence

- All 11 media Motoko test files pass, including sparse read/release/reuse across 32 GiB and at the candidate's physical boundary, and bounded refusal without mutation.
- 30 operator/enlargement/journal/funding-policy tests pass.
- Real PocketIC upgrade from the saved pre-change 32 GiB module: old setting remains 32 GiB until explicitly raised; 64 GiB setting survives a second memory-preserving upgrade; committed bytes and partially uploaded bytes survive both; completion, deletion, abort/retry reuse and exact totals pass; unauthorized and above-64 GiB updates are denied.
- Combined gallery/vault/chat Pro allowance actor test passes.
- `mops build` succeeds with pinned Motoko 1.16.1. That compiler's `--help` reports the default Region ceiling as 1,638,400 pages = 100 GiB, above this candidate. Older documentation describing a 4 GiB default does not describe this pinned compiler. The production recipe uses `mops build`; workflow module fingerprints remain generated by the pinned ICP build, not the local hash.

Reproduction: save the prior release photo-store Wasm before compiling this candidate, then run:

```sh
# From backend/media_blob_store
mops test
mops build
# From project root; replace the old-module path with the prior release artifact
MEDIA_PREVIOUS_WASM=/path/to/prior-32gib.wasm node frontend/scripts/test-media-minimum-capacity-replica.mjs
POCKET_IC_BIN=/root/.cache/mops/pocket-ic/15.0.0/pocket-ic node frontend/scripts/test-media-pro-allowance-replica.mjs
```
