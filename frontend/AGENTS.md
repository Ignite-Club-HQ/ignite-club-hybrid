- App lives under frontend/; live target in live/targetRegistry.ts, ICP agent in live/icpAgent.ts. Canister IDs from IGNITE_LIVE_ICP_CANISTER_IDS_JSON; no fixtures/credentials in bundle. createLiveAgent caches one HttpAgent per target+principal (clearLiveAgentCache on sign-out) — handshake else paid per actor.
- Runtime canister config: admins edit IDs at /admin/placement-settings (/admin/icp-canisters redirects); stored in app_settings icp_canister_config, loaded via loadIcpAdminOverrides.ts, merged in getActiveIcpTarget() — canisters deploy after build, so IDs must be runtime-configurable. Build-time default: scripts/sync-canister-ids.mjs (run by dev-preview/build-preview) regenerates live/generated/deployedCanisterIds.ts from deploy/mainnet/.icp/data/mappings/ic.ids.json; targetRegistry falls back to it when IGNITE_LIVE_ICP_CANISTER_IDS_JSON is unset. Precedence: admin overrides > env JSON > generated table.
- icpAdminOverrides.ts must not import the Supabase client (targetRegistry->overrides->supabase->liveClient cycle); Supabase access in loadIcpAdminOverrides.ts.
- Backend routing (default backend, country eligibility, targets/pins) in live/backendRouting.ts (pure, same cycle rule); stored in app_settings backend_routing_config, loaded via loadBackendRouting.ts, country via userCountry.ts.
- Media bytes: live/mediaStorage.ts (pure) resolves blob_ref -> ICP URL else Supabase path; uploads via live/mediaUpload.ts only with blob-store ID + II session; failures throw. Blob-store uploads are IBE-encrypted client-side first (identity `storagePath ++ U+001F ++ "blob"` via live/piiVetKeys.ts) and MUST register the matching pii_access_control record (pii_id=storagePath, field_id="blob", owner=uploader) — registration failure fails the upload (orphaned ciphertext is undecryptable by everyone); club read grant from a `clubs/<clubId>/` path prefix is best-effort. Reads: live/mediaDecrypt.ts detects blob-store URLs, fetches ciphertext, derives the vetKey through the gated relay, decrypts, and returns an object URL — never fall back to the raw URL (it serves only ciphertext). blob: URLs are kept out of the persisted signed-URL cache (session-scoped).
- /auth screen (Supabase vs Internet Identity) from live/authBackendMode.ts (routing config + country + canister availability); App.tsx gates first paint on placement load before picking auth provider. Never reuse resolveLocalAuthMode here — lab call sites stay false in the live build. Feature routing: withFeatureBackend (live/featureRouter.ts), pure map live/featureBackend.ts; ICP only when its canister ID is set; provisional id mappings until verified on deployed canisters. SIMULATED_TARGET (dry-run) must never reach the routing store or real traffic. Also routed: duty completion, vault rename/move/delete, notification fan_out, announcement broadcast; push + open duties stay Supabase.
- Per-club backend overrides: backend_routing_config.clubBackendOverrides (club id -> supabase|icp) pins every member's whole app (features + /auth screen); a Supabase pin beats an ICP pin on conflict, ICP pin still needs canister IDs. Post-auth resolution uses live membership (userClubs.ts, loaded by ClubBackendEnforcement.tsx); pre-auth uses the cached club-backend hint in backendRouting.ts. Enforcement signs out + reloads once per session on pin/provider mismatch — never loop.
- PII writes (live/features/vault.ts helpers): child names -> pii_access_control pii_id=child id/field_id="name" (registerLiveChildNamePii, creator is domain owner + grant to parent, plus grantLiveClubChildNameRead at every child-creation site so club members can render roster names); invite emails -> pii_id=invite id/field_id="email" (inside createLivePendingInvite); own display name -> pii_id=principal text/field_id="display_name" (EditProfilePage ICP branch). All best-effort (log, never throw) — matches acceptParentInvite's guardian-grant pattern. createLiveChildForParentOnTeam signature is (ctx, clubId, teamId, parent) — the canister takes no name; names never go to club_domain.
- PII name references on events_domain: event guest names (EventGuestsManager), fill-in player names and MVP names (live/features/events.ts save paths) are registered on pii_access_control under opaque refs — guest:<eventId>:<uuid> field "guest_name", fillin:<eventId>:<uuid> and mvp:<eventId> field "name" — with a club-scoped read grant (club id derived from the team id); only the ref is stored on the canister. Reads resolve refs via resolveLivePiiTextBatch (child roster names use pii_id=child id/field "name"); values not matching a ref prefix are legacy plaintext and render as-is; an unreadable ref renders as a neutral label, never an error state. Adult display names intentionally stay plaintext on identity_access — member search depends on them (public directory data by design).
- Entry-chunk rule: files reachable at app start (App.tsx, layout, app-wide hooks/libs) must NOT statically import @/live/features/*, live/domains, live/icpAgent, live/piiVetKeys, live/identityAccess, or @icp-sdk/* — use await import() at the (async) call site. Why: static imports pull the whole ICP SDK + candid bindings (~760KB rendered) into the boot chunk even when no canisters are configured.
